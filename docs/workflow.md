# Blenderでアバターを仕上げる工程

この文書は、アニメ調のオリジナルアバターを無料の制作環境で作るための工程案。特定モデルの完成実績や、すべての出力先での動作保証を示すものではない。

## 制作原本と出力を分ける

編集用の `.blend` を正本にし、髪のカーブ、法線転送用の補助形状、比較用カメラを保持する。VRMやFBXは派生データとして作り、書出し後の最適化結果で原本を上書きしない。第三者素材を使う場合は、取得元、取得日、版、利用条件をモデルとは別に記録する。

追加ツールを選ぶ前に、三角形数、UVの有無、材質、骨、表情を調べる。Blender内の集計と出力先SDKの集計は別に記録する。面数は負荷の目安であり、造形品質の点数にはしない。

## 形から表情へ進める

| 工程 | 作業 | 次へ進むための確認 |
| --- | --- | --- |
| 大きな形 | 頭身、顔の比率、髪と服の輪郭を決める | 正面・側面・背面・斜めで意図した特徴を読める |
| 顔と髪 | 頬、目、横顔、主要な髪束を整える | 同条件の新旧比較で改善を判断できる |
| 陰影 | 法線、材質、光を一つずつ調整する | 光を回しても意図しない黒い割れが目立たない |
| UVと塗り | 色、毛先、瞳、衣服の柄を描く | 明暗背景と小さな画像でも顔が読める |
| 表情 | 閉眼、口形、感情表情を作る | 単独表情と組合せで瞼・口が破綻しない |
| 変形 | 肩・肘のウェイト、髪や装飾の干渉を整える | 腕下ろし、腕水平、肘曲げ、腕上げ、首回しを確認できる |
| 出力 | 用途別データを作る | 再読込みと対象アプリで形・色・動きを確かめる |

各段階の合格は制作者が見た目を判断する。三面図との一致だけでは、透視投影や動作時の品質を判定できない。

## 髪と衣装の作り方

髪は全体の量感、主要な束、輪郭付近の小さな束の順に作る。カーブの断面・幅・厚み・先細りを残しておくと、密度を上げる前に流れを直せる。UVは根元から毛先への方向を揃え、形、色、ハイライト、揺れを別々に調整する。

衣装は肩の落ち方、裾と袖口の絞り、布が余る位置を先に決める。布計算や高密度造形は、しわの参考と静止形状の制作にも使える。常時布シミュレーションを実行するアバターを前提にしない。関節の潰れはまずウェイトで直し、補正モディファイアを使う場合も出力先で同じ処理が動くかを分けて確認する。

## 比較を再現できるようにする

- カメラ、解像度、照明、露出を固定し、新旧を並べる。
- 形だけ、法線だけ、色だけの比較を用意する。
- 正投影の多方向画像と、会話距離の透視投影を併用する。
- 無表情に加え、笑顔と閉眼などの組合せを検査する。
- 原本、書出し後の再読込み、対象アプリの確認結果を区別して残す。

比較工程の参考は、Blender Studioの[Automatic Model Sheets](https://studio.blender.org/blog/automatic-model-sheets/)。形の情報量を選ぶ参考は[Sprite Fright: Illusion of Simplicity](https://studio.blender.org/blog/sprite-fright-the-illusion-of-simplicity/)。上の工程はこれらを踏まえた独自の提案であり、配布テンプレートや映画用リグは同梱しない。

## 出力先ごとの受入条件

| 用途 | 確認すること |
| --- | --- |
| Blenderでの静止画 | 輪郭、光、透過縁、撮影用効果。撮影専用の処理を制作原本から識別できること |
| VRM | 対象VRM版、材質、法線、表情、骨、揺れ。利用アプリで実際に追従すること |
| VRChat | 対応Unity・SDK、材質、揺れ、視点、動作、SDKによる性能評価 |

[MToonの説明](https://vrm.dev/en/univrm/shaders/shader_mtoon/)と[VRChatの性能基準](https://creators.vrchat.com/avatars/avatar-performance-ranking-system/)は導入時に再確認する。Blenderの独自ノード、ドライバー、モディファイアがそのまま移るとは扱わない。書出し成功と実機確認は別の完了条件にする。
